# Maintaining the UCS fonts mirror

This guide is for maintainers, contributors, and anyone reproducing or refreshing the mirror.
For downloads and licensing information, see the [README](README.md).

## Prerequisites

Use Bash 3.2 or newer on macOS or Linux; on Windows, use WSL.
You need Git, curl, [`uv`](https://docs.astral.sh/uv/), standard Unix command-line tools,
and either `shasum` or `sha256sum`.
Run the commands below from the repository root.

## Rebuild

From the repository root:

```bash
./run mirror
```

The Bash script discovers download links from the upstream font page
and walks the linked examples directory,
including any nested directories.
It does not crawl the rest of the author's website or external sites.
Images and any paths in `scripts/excluded-paths.txt` are omitted.
There is no hard-coded list of files to download.
Archives are never unpacked or executed.

The script reports progress,
downloads original bytes,
records provenance in `docs/SOURCES.tsv`,
and updates both SHA-256 manifests and `docs/_data/mirror.yml` with a UTC timestamp.
Edit the Markdown, layout, configuration, and styles in `templates/`, then rebuild;
`docs/` is generated output.
The site's full directory view is populated automatically from the mirrored files.

## Setup

`mirror`, `prek`, and `tests` invoke setup first.
Setup installs prek through uv when it is absent from `PATH`;
an existing installation is left alone unless setup is forced.
If the pre-commit hook is missing, setup installs the configured hooks.
If that hook was generated by pre-commit, setup force-replaces the configured hooks.
Otherwise, existing hooks are left alone unless setup is forced.

`._done-setup-prek` caches the entire successful setup, including hook checks.
`./run setup` honors this cache.
`./run setup force` bypasses the marker, installs or upgrades prek,
and replaces existing hooks.

## Test

```bash
./run prek
./run tests
```

The tests are isolated and offline;
uncached runner setup may access the network.
To run tests without runner setup, use `bash tests/tests`.
Formatting hooks exclude generated `docs/` files.
Git newline conversion is disabled for downloads and examples.
Do not repair whitespace, encoding, or invalid bytes in the original sample files.
The read-only checksum checker verifies the assets and agreement between both manifests.

## Publication and recovery

The complete site is staged and checked before replacing `docs/`.
Download, hashing, template, or link failures preserve the previous snapshot.
Publication failures roll back the site and external manifest together.
An exclusive `._mirror-lock` prevents overlapping publication and rollback.
If cleanup cannot complete, the script reports retained recovery files and keeps the lock.
Remove a stale lock only after confirming no mirror is running and handling recovery files.

## GitHub Pages and weekly updates

After creating a GitHub repository and pushing to `main`,
set **Settings > Pages > Source** to **GitHub Actions**.
The publishing workflow builds `docs/` with Jekyll
and deploys changes pushed to `main`.
It also has a manual trigger.
If the default branch changes, update `push.branches` in `.github/workflows/pages.yml`.

The refresh workflow runs Mondays at 05:36 UTC, with an additional manual trigger.
It uses the mirror and checksum scripts directly, without installing development hooks.
`scripts/commit-mirror.bash` stages generated output and commits content changes as
`github-actions[bot]`.
Timestamp-only changes do not create commits.
The published time therefore records the last committed snapshot, not the last scheduled check.

After each successful check,
the workflow explicitly invokes Pages publication from a fresh checkout of the committed snapshot.
This is necessary because pushes made using `GITHUB_TOKEN` do not trigger ordinary push workflows.
It also lets the next weekly run recover from a failed deployment even if upstream is unchanged.
No extra token secret, workflow retry loop, back-off, or force push is used.
Repository rules must allow workflow pushes to the default branch.
GitHub may delay schedules or disable them after 60 days of public-repository inactivity;
re-enable the workflow in Actions if needed.
